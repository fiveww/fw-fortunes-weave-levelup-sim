# 火纹 Fortunes Weave 加点模拟器(网页离线版)

《Fire Emblem: Fortunes Weave》升级加点机制的逆向复刻工具:录几级加点观测,反推出角色的乱数种子,进而确定预测此后每一级的加点,直到 99 级。

零依赖、无构建、数据不出浏览器——双击 `index.html` 即用,离线可用,手机同样能跑。

- **位精确**:算法按反汇编规格逐位移植,页面加载即跑 28 项黄金向量自检
- **全空间反推**:多线程扫描 2^31(可含 2^32)种子空间,3 级观测典型收窄到个位数候选
- **可选高速引擎**:附带 10KB WASM 引擎,扫描提速约 84 倍(见下文专章)
- **完整推演**:支持转职消耗种子、坐骑好感档、逐级种子链展示、预测表导出

## 快速开始

三种打开方式,任选其一:

| 方式 | 做法 | 说明 |
|---|---|---|

## 升级加点机制(逆向结论)

以下规则逆向自 Switch 版主程序,经黄金向量与实测种子链验证。

**种子与乱数链。** 每个角色有一个独立的 32 位升级种子。每次升级结算时,游戏用这个种子现场初始化一组四状态字的 xor128 乱数发生器(初始化乘法常数是 `0x6C078965`——比标准 MT19937 大 0x100,本作独有),掷完点后种子按一个纯函数推进到下一个值。升级与**转职共用这条种子链**:转职同样吃掉一个种子,但只推进、不加点。因此只要知道种子,角色之后每一级的加点完全确定;反过来,录下几级的加点观测,就能在种子空间里把种子扫出来。

**一次升级的四个阶段。**

1. **资格**:成长率 ≥ 1 且当前值 < 上限的属性进入候选列表,其余不参与;
2. **掷点**(最多 4 轮):每个候选属性消耗一个乱数,`RN % 1,000,000 < 残差 × 10,000` 则该属性 +1;成长率的整百部分(`g // 100`)是保底基数直接加上;残差为 0(整百成长)不耗乱数。一轮掷完若非零项数已达门槛 `max(1, min(gc, n))` 即停,否则整轮重掷;
3. **保底补足**:若非零项不足 `min(gc, n)`,每缺 1 点抽一个乱数,按各零增益属性的成长率 × 100 加权走表,选中的属性 + 1;
4. **落地**:逐点复查上限,把决定增益截断为实际落地增益。

其中 gc 是职业数据中的"每级保底点数"(真值未确证,默认按 2 处理,页面可改)。升级画面闪烁展示的是第 2、3 阶段后的**决定增益**——观测录入与过滤比对都用它。

**成长率合成。** 生效成长率 = 人物成长 + 职业成长 + 坐骑成长(按好感 1–5 档取值;战车系职业的坐骑成长 ×2)。

## 使用方法:从观测反推种子

**第一步,选角色。** 左侧"角色"面板选人物、职业、坐骑与好感档,下方表格实时显示四行成长率与最终合成值。

**第二步,录观测。** "观测计划"表每行对应一次升级,列含义:

- **等级**:该行是几级升几级;改某行等级后,后续行自动顺延
- **升级前的转职跳过次数**:这一级之前转职吃掉的种子数(默认 0;转一次填 1)
- **升级时职业 / 坐骑 / 好感**:该级生效的配置,改动从该行起向后延续
- **加点观测**:点击格子 0↔1,右键或 Shift+点击 = +2(成长率 ≥ 100 时会出现 +2),按升级画面实际加的点录入
- 没录过的级把该行"观测"开关关掉——它仍然消耗种子,只是不约束过滤

**第三步,过滤。** 点「开始过滤(全扫描)」,最多 8 线程扫描 `0 .. 2^31-1`(勾选"含 32 位区"扩展到 2^32,用于从未升过级的单位)。观测 ≥ 5 条时命中 1 个候选即停。扫完列出全部候选种子。

**第四步,收窄。** 之后每录一级新观测,点「用当前观测在候选内收窄」,在已有候选内本地秒级过滤,无需重扫。

**第五步,看预测。** 候选唯一时自动选中;预测表从观测最低等级一路列到 99 级,每行显示该级所用的种子与预测加点。预测表所有行同样可编辑(跳过次数、职业、坐骑、好感),可自由改配置做推演——比如"从这里转职会怎样"。多候选时会统计前 1000 个候选的未来一致性:完全一致则预测可信,有分歧则可逐个切换候选查看。

**其他功能**(左侧"高级"面板):

- **已知种子直模拟**:已经拿到种子(如上次反推或外部工具输出)时,直接填入模拟,跳过过滤
- **导出 / 导入预测表**:JSON 格式,含种子、人物与整表计划,便于存档和分享
- 右上角**重置**:清空本次人物/观测/候选/预测,准备下一个角色(已启用的引擎保留)

## 高速引擎(WASM,可选)

默认扫描走浏览器 JS,8 线程约 12M 种子/秒,全扫 2^31 约 3 分钟。本目录附带的 `few_engine.wasm` 是同一套匹配算法的 C 编译版(freestanding WebAssembly 模块,仅 10KB):单线程实测约 256M 种子/秒——**约为 JS 的 84 倍**,8 线程全扫 2^31 只需几秒。

### 启用步骤

1. 打开页面,在左侧「高级」面板点 **「启用高速引擎(选择引擎文件)」**
2. 在文件选择器中选中与本页面同目录的 **`few_engine.wasm`**(页面会校验 WASM 魔数)
3. 状态变为"已启用(扫描自动走 WASM 高速引擎)"即生效

之后所有扫描自动改走 WASM,线程数与其他行为(进度条、首中即停、候选上限、收窄)与 JS 模式完全一致,无需任何额外操作。

### 说明

- 引擎文件经 base64 存入浏览器 localStorage,**选择一次长期记忆**,重启浏览器不用再选;点「停用」可移除
- `file://` 直开与 `http://` 访问的存储相互隔离,换打开方式需重新选择一次
- **全平台通用**(含 iPhone):把 `few_engine.wasm` 传到手机,在页面里选一次即可;单文件版 `few_sim_single.html` 同样支持
- 每个扫描线程独立实例化引擎,互不干扰

### 重新编译

```sh
zig cc --target=wasm32-freestanding -O3 -nostdlib -Wl,--no-entry \
  -Wl,--export=cfg_addr -Wl,--export=out_addr -Wl,--export=scan \
  -o few_engine.wasm few_engine_wasm.c
```

引擎源码 `few_engine_wasm.c` 约 200 行、无 libc 依赖,核心与 JS 匹配器逐位对拍验证一致。

## 数据与假设

为诚实起见,当前预设数据的边界:

- **gc(每级保底点数)真值未确证**,默认 2,页面可改;与实测对不上时优先试这个
- **坐骑数值为满好感(5 档)的整理值**,好感 1–4 档暂无数据、按 0 处理
- **职业上限在预设里暂填 99**,上限判定基本不生效;属性累计从 0 起算,不录角色当前值
- 职业 / 坐骑数值以人工整理校准的数据表为准,人物成长取自游戏文件 Person.bin 提取
- 转职是否把属性拉到新职业下限:未验证,不模拟
- 界面按游戏展示序显示属性,内部按引擎序计算(技巧/速度、幸运/防御位置互换),页面自动换算
